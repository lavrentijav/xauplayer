# API Обновлений

## GET `/version`

Проверка наличия обновлений приложения.

**Request:**
- Метод: `GET`
- URL: `{update_url}/version` (где `update_url` - базовый URL из настроек, например `https://api.xau.fire-core.ru/version`)
- Headers: не требуются

**Response:**

Успешный ответ должен быть в формате JSON со следующими полями:

```json
{
  "version": "1.2.3",
  "build_number": 42
}
```

### Поля ответа:

- **`version`** (string, обязательное) - версия приложения в формате семантического версионирования (например, "1.2.3", "2.0.0"). Это отображаемая версия для пользователя.

- **`build_number`** (integer или string, обязательное) - номер сборки (versionCode). Это числовой идентификатор версии, который используется для сравнения. 
  - Может быть числом: `42`
  - Или строкой, которая может быть преобразована в число: `"42"`
  - Если `build_number` равен `0` или отсутствует, приложение считает, что обновление не требуется

### Логика определения необходимости обновления:

1. Приложение получает текущий `versionCode` из `PackageManager`
2. Сравнивает его с `build_number` из ответа сервера
3. Если `build_number > versionCode` → обновление доступно
4. Если `build_number <= versionCode` или `build_number == 0` → обновление не требуется

### Примеры ответов:

**Обновление доступно:**
```json
{
  "version": "1.5.0",
  "build_number": 15
}
```

**Обновление не требуется (текущая версия):**
```json
{
  "version": "1.4.0",
  "build_number": 14
}
```

**Обновление не требуется (если build_number = 0):**
```json
{
  "version": "1.4.0",
  "build_number": 0
}
```

### Ошибки:

**HTTP 404 или другой код ошибки:**
- Приложение покажет ошибку "HTTP {code}"
- Обновление не будет доступно

**Некорректный JSON:**
- Приложение покажет ошибку "Unknown error"
- Обновление не будет доступно

## GET `/release`

Скачивание APK файла обновления.

**Request:**
- Метод: `GET`
- URL: `{base_url}/release?os_type=android&arch={architecture}`
- Параметры:
  - `os_type` (обязательный) - всегда `"android"`
  - `arch` (обязательный) - архитектура устройства:
    - `"arm64"` - для ARM 64-bit (наиболее распространено)
    - `"arm"` - для ARM 32-bit
    - `"x64"` - для x86_64
    - `"x86"` - для x86

**Response:**
- Content-Type: `application/vnd.android.package-archive` или `application/octet-stream`
- Body: бинарный файл APK

**Пример запроса:**
```
GET https://api.xau.fire-core.ru/release?os_type=android&arch=arm64
```

### Формирование URL для скачивания:

Приложение автоматически формирует URL следующим образом:
1. Берет `update_url` из настроек (например: `https://api.xau.fire-core.ru/release`)
2. Заменяет `/release` на пустую строку, получая базовый URL: `https://api.xau.fire-core.ru`
3. Определяет архитектуру устройства
4. Формирует финальный URL: `{base_url}/release?os_type=android&arch={arch}`

**Пример:**
- `update_url` = `https://api.xau.fire-core.ru/release`
- `base_url` = `https://api.xau.fire-core.ru`
- `arch` = `arm64`
- Финальный URL = `https://api.xau.fire-core.ru/release?os_type=android&arch=arm64`

## Рекомендации по реализации на сервере:

1. **Версионирование:**
   - Используйте семантическое версионирование для `version` (MAJOR.MINOR.PATCH)
   - `build_number` должен монотонно увеличиваться с каждой новой сборкой

2. **Проверка архитектуры:**
   - Сервер должен возвращать APK файл, соответствующий запрошенной архитектуре
   - Если APK для конкретной архитектуры недоступен, можно вернуть универсальный APK или ошибку 404

3. **Кэширование:**
   - Приложение проверяет обновления не чаще раза в 24 часа (настраивается в `UPDATE_CHECK_INTERVAL_MS`)
   - Сервер может использовать стандартные HTTP заголовки кэширования

4. **Безопасность:**
   - Рекомендуется использовать HTTPS для всех запросов
   - APK файлы должны быть подписаны правильным сертификатом

## Пример полного цикла обновления:

1. **Проверка обновления:**
   ```
   GET https://api.xau.fire-core.ru/version
   Response: {"version": "1.5.0", "build_number": 15}
   ```

2. **Сравнение версий:**
   - Текущая версия приложения: `versionCode = 14`
   - Версия на сервере: `build_number = 15`
   - Результат: `15 > 14` → обновление доступно

3. **Скачивание APK:**
   ```
   GET https://api.xau.fire-core.ru/release?os_type=android&arch=arm64
   Response: [бинарный файл APK]
   ```

4. **Установка:**
   - Приложение сохраняет APK во временную директорию
   - Запускает системный установщик через Intent
